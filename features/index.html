It operates your apps, then checks.

ATOM works through Android’s accessibility service. It reads the screen, then taps, types, swipes and scrolls the way you would. When a direct tool is faster and more reliable, it uses that instead: Do Not Disturb, volume, brightness, alarms, timers, media and the flashlight.

After it acts, it looks again. It reports a task as done only when the screen or the setting shows it. If it can’t confirm something worked, it says so and tells you what it saw.

  • Every step appears in the chat with its arguments and how long it took.
  • Long tasks keep going while they make progress. Continue picks up a run that hit its step limit.
  • With the screen off, background work carries on. Screen tasks wait until you unlock.
  • With root or Shizuku it can go further: freeze apps, change protected settings, read logs.

A bubble over any app, and the assistant gesture.

The floating bubble sits over whatever you’re doing and stays where you leave it.

  • Tap it for a mini chat that stays on top of the app.
  • Hold it for quick actions: voice, chat, close.
  • Drag it anywhere on the screen.

You can also set ATOM as the phone’s assistant. A long press of the power button then opens it, already aware of what’s on screen. That costs nothing in the background: no microphone, no service running.

While a task runs, a small capsule shows its progress over other apps, with Stop one tap away.

Your context, one permission at a time.

ATOM can use what your phone already knows. It uses only the part a task needs, and only after you allow it.

  • Notifications: what’s showing now and a 7-day history, for questions like “what did I miss?”
  • One-time codes from your messages.
  • Calendar: read, create, change and delete events.
  • Contacts, files and location.

Nothing is asked at first launch. Each permission is asked once, when a feature first needs it, with one sentence saying why. If you say no, that feature turns off and ATOM doesn’t keep asking. See every Android permission ATOM uses.

A terminal and real Linux, no root needed.

ATOM has a full terminal with several sessions: the Android shell, a root shell if you have root, and Linux.

Linux runs on the phone: Alpine or Debian. Standard mode uses PRoot and needs no root. Root mode uses a chroot in its own mount namespace, at native speed.

The base tools come installed:

  • git
  • curl
  • jq
  • rg
  • fd
  • ssh
  • sqlite3
  • nano
  • htop
  • python
  • node
  • Python (with uv), Node.js and npm, an OpenSSH server and APK analysis tools install on request.
  • Every download is checked: distro packages by their signatures, the rest against published SHA-256 sums.
  • Background commands keep running and notify you when they finish.

The agent uses it too. It writes code, runs it, reads the errors and fixes them. How to run Linux on Android without root.

Scheduled tasks and phone-event automations.

Scheduled tasks run a request on a schedule, such as “weekdays 07:45” or “every 2h”, and report back by notification. Each one can use its own model and its own set of capabilities. You choose whether it notifies on every run, only when the result changes, or silently.

Automations react to the phone: charger connected, battery level, screen on, unlocked, Wi-Fi or Bluetooth connected, headphones, Do Not Disturb or airplane mode changes, arriving at or leaving a place, a notification from an app, an app opened, or the phone starting up.

Describe one in a sentence. ATOM builds it once into a trigger, conditions and steps. No model runs when the event fires unless a step needs one.

4.0.6 adds ready-made routines: Morning brief, Price watch, Weekly phone cleanup and Evening wrap-up. How to automate Android with plain sentences.

Any model you like.

14 providers built in: OpenAI, Anthropic, Gemini (AI Studio and Vertex AI), DeepSeek, Qwen (Alibaba Bailian), Kimi, MiMo, MiniMax, StepFun, SiliconFlow, OpenRouter, xAI, Groq and Mistral.

  • Anything compatible: any OpenAI- or Anthropic-compatible endpoint, including llama.cpp or Ollama on your own computer, plus the models.dev catalog.
  • Subscriptions: sign in with a ChatGPT or Grok account instead of an API key. This is experimental; an API key is the recommended way.
  • Per conversation: pick the model and the reasoning effort, from Off to Max, within what the model supports.
  • Per job: separate models for the floating assistant, subagents, titles and scheduled tasks.

How to use your own model or a ChatGPT subscription on Android.

Fully offline, on the phone.

The app stays at 7 MB because on-device AI is an optional pack of about 32 MB. It downloads only from ATOM’s own GitHub release and is checked against its published SHA-256 and the app’s signing key.

With the pack, ATOM runs models on the phone with LiteRT-LM (GPU accelerated) and llama.cpp (GGUF). One tap downloads a recommended model such as Qwen3 0.6B or Gemma 4 E2B and sets it up. You can also add any .litertlm or .gguf file from a link.

The pack also runs the on-device “Hey ATOM” wake word. If the phone gets hot or the battery runs low, on-device inference pauses. A cloud fallback takes over only if you set one.

Memory, skills, MCP and more.

  • Memory you can read and edit: one Markdown file that ATOM keeps up to date, with a core section sent with every message.
  • Skills: instruction packs installed from any public GitHub repository or a ZIP.
  • MCP servers over Streamable HTTP, with a switch for each tool. How to use MCP servers on Android.
  • Subagents: explore, coder and plan, plus your own, each working in its own context.
  • Voice: dictation, spoken answers and the on-device “Hey ATOM” wake word (needs the pack).
  • An agent browser you can take over, plus web search and page reading.
  • Image generation and editing with the image service you choose.

You stay in charge.

  • Shell commands ask first. One tap allows all commands for the rest of that task. Commands that look destructive still ask.
  • Optional “ask before taps and typing” lets you approve every step.
  • Stop always works: from the chat, the run capsule or the notification.
  • Undo history: every change ATOM makes to the device is recorded, with one-tap undo.
  • Locked means locked: over the lock screen ATOM only shows that a task finished. To approve anything, you unlock first.
  • Every tool has its own switch, and it takes effect even mid-task.

Things you can ask.

  • “What’s the OTP that just came in?”
  • “Open WhatsApp and tell Rahul I’ll be 10 minutes late.”
  • “Turn on Do Not Disturb and set an alarm for 6:45.”
  • “Every weekday at 7:45, give me my calendar and anything urgent in my notifications.”
  • “When I plug in the charger after 11 PM, turn on Do Not Disturb.”
  • “Look at my screen and explain this error.”
  • “Clone this repo, run its tests and tell me why they fail.”

Honest limits.

  • Small models are weak agents. On-device models handle chat and simple tool calls. For long, multi-step app tasks, use a strong cloud model.
  • App control goes through accessibility. It’s slower than your thumb, and apps that hide their screens from accessibility can’t be operated.
  • PRoot is slower than native. Some software won’t run in it.
  • Tested on emulators. CI covers every change, but real-phone battery numbers aren’t measured yet.
  • English only, on ARM64 phones with Android 14 or newer.

Private by design.

No telemetry, no analytics, no account and no ATOM server. API keys are encrypted with a key held in the Android Keystore. Messages go only to the model provider you pick, or nowhere with on-device models. Web searches go to the search engine you set. The only automatic call to GitHub is the update check, when you open About or tap Check for updates. Read ATOM’s privacy policy.
