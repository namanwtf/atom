Privacy policy

Atom collects nothing about you. It has no account, no telemetry, no analytics and no server of its own. This page explains, in plain words, what stays on your phone, what leaves it and where it goes.

Effective 27 November 2026Applies to the Atom app (io.github.namanwtf.atom) and this website

The short version

  • The developer of Atom receives no data from the app. There is no Atom server to receive it.
  • Your chats, memory, files, schedules and settings are stored on your phone.
  • Your messages go only to the model provider you choose, or nowhere if you use an on-device model.
  • Every permission is asked only when a feature first needs it, and you can say no.

What stays on your phone

  • Conversations, long-term memory, files in the workspace, scheduled tasks, automations, skills and settings.
  • The Linux environment and everything in it.
  • API keys, sign-in tokens and MCP tokens, encrypted with a key held in the Android Keystore.
  • Context Atom reads for a task, such as notifications, messages, one-time codes, calendar, contacts, files and location. It is read on the phone when a task needs it. Only what goes into a request to your model provider leaves the phone (see below).
  • A history of the changes Atom makes to the device, kept so you can undo them.

This data is kept until you delete it in the app, clear the app’s storage or uninstall Atom. Android’s cloud backup is turned off for Atom. Settings → General → Data backup exports your data to one JSON file only when you ask. That file includes your model provider API keys in readable form, so store it privately. Speech credentials and sign-in tokens are never included.

What leaves your phone, and to whom

Atom connects only to services you choose or start. Each of them handles your data under its own privacy policy.

Atom never sends anything to a plain http:// address you didn’t type yourself, and all built-in cloud providers use HTTPS. There are no background calls: no telemetry, no crash reporting, no analytics and no advertising identifiers.

Report a problem (from 4.0.6) builds a report on the phone, with keys, tokens and personal data removed. Nothing is sent automatically: you read the report and decide whether to share it.

Permissions

Atom asks for each Android permission the first time a feature needs it, with one sentence saying why. If you say no, that feature turns off and Atom doesn’t keep asking. You can change any of them later on the Permissions page or in Android’s settings.

  • Accessibility service: reads the screen and taps, types and scrolls for tasks you start.
  • Display over other apps: the floating bubble and run capsule.
  • Notifications, SMS (for codes), calendar, contacts, call log, files, location, microphone, usage access and Health Connect: each only for the features that use it.

The full list, with what uses each permission and when it is asked, is in docs/PERMISSIONS.md.

On the lock screen

While your phone is locked, Atom shows only that a task finished, not its content. To see results or approve an action, you unlock first.

This website

This site is a set of static pages. It sets no cookies, uses no analytics or trackers, and loads nothing from other servers: fonts, images and video are served from the site itself. It is hosted on GitHub Pages, and GitHub may log technical data such as IP addresses to run and secure the service, as described in GitHub’s privacy statement.

Children

Atom is a general-purpose tool and isn’t directed at children. It collects no data from anyone.

Changes to this policy

If this policy changes, the new version is published on this page with a new effective date. Every change is visible in the website’s public history on GitHub.

Contact

Questions or concerns about privacy: open an issue at github.com/namanwtf/atom/issues. Please don’t include personal data, keys or tokens in a public issue.
